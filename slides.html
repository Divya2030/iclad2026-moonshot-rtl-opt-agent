Verification-Gated RTL Optimization

Optimize aggressively with an LLM — ship only what's proven correct. A Gemini agent rewrites RTL for power/performance/area; a formal + simulation gate refuses any rewrite that changes behavior.

T16 Moonshot · ICLAD 2026

The problem & how it's scored

Correctness is the gate. PPA is the prize. Hidden tests are the judge.

  • Use an LLM agent to optimize IP RTL — async_fifo, sha512, NVDLA, OpenTitan AES / ASCON / PRIM / KMAC.
  • Two-phase scoring: functional correctness first → then PPA (Yosys / OpenSTA) + LLM calls & token cost.
  • Winners judged at DAC on hidden testcases — passing the visible testbench is not enough.

Consequence

An "optimization" that looks smaller/faster but is subtly wrong scores zero — and hidden tests are built to find it. So correctness-under-uncertainty is the real competition.

Key insight · our thesis

The failure mode that loses the hackathon is a silent functional regression.

  • We proved it's real: a candidate with lower area that passed simulation but was formally inequivalent — and the reverse.
  • Thesis: make formal equivalence a hard gate inside the optimization loop.
  • Then the agent can chase PPA hard, because the gate — not the model — decides what ships.

PPA-only optimizer

Fast. Passes the visible bench. Ships silent bugs → fails hidden tests.

Verification-gated

Fast and safe. Aggressive rewrites, zero accepted regressions.

Agent design · the proposer

Transformation-driven, not "make it smaller."

  • Sees the real synthesis bottleneck — sequential vs combinational area, dominant cell types.
  • Handed a transformation menu grounded in RTLRewriter / ROVER / ASPEN (register, FSM, resource-sharing, operator-restructuring, width, boolean, strength).
  • Told not to repeat what Yosys + ABC already do; keeps rejection memory across rounds.
  • Emits surgical edits or whole-file rewrites; records LLM calls + tokens (the scored cost).

The verification gate

Three gates, one verdict.

SIM

The scored correctness check — SVUT / Icarus / plain-Verilog TBs. Hard gate.

EQUIV

Yosys-native sequential equivalence (bundled SAT + ABC — no external solver, runs in the eval Docker as-is).

PPA

Yosys synth + OpenSTA on ASAP7 — area, WNS, worst-slack, power, plus a cell-level bottleneck.

Timing = relative

Reject only on WNS regression — designs can start timing-negative (sha512 −169 ps).

Tiered equivalence · a real finding

XOR/parity datapaths are SAT-hard — so we tier the evidence, honestly.

provenformal proof converges → highest confidence
sim-verifiedformal inconclusive → directed + 20k-vector miter passes
refutedmiter finds a mismatch → hard reject
  • Measured: the CRC "flatten" defeated both Yosys-native equiv and ABC SAT-sweeping CEC (each > 6 min timeout).
  • Confidence level travels with every verdict — we don't pretend everything is proven.
  • Future: XOR-aware EC (eqy / CryptoMiniSat) or our GF(2) linear checker to reclaim proven.

Case study · the CRC datapath flatten

A hard, high-value rewrite — correctly gated.

  • Bottleneck: 4-deep serial byte-CRC chain (~14 logic levels) → WNS −282 ps.
  • Rewrite (ASPEN-style): collapse the linear recurrence into one depth-~5 GF(2) XOR network.
  • Result: WNS −282 → −9 ps (timing essentially closed), area +59% (tradeoff), 5000-vector miter PASS.
  • Formal equiv timed out (XOR-hard) → accepted sim-verified; a 1-term corruption → refuted.

Cost & efficiency

Token & call cost is a first-class metric.

  • The loop records usage (LLM calls, input/output tokens) every run and adopts only on measured improvement — no churn.
  • Levers: bottleneck-targeted prompts (fewer wasted turns), rejection memory (no repeats), synth caching per candidate.
  • Autonomous run cost: [live] — N calls, M tokens to reach the reported wins.

The scoring counts calls/tokens; we treat efficiency as designed-in, not incidental.

Honest limitations & what's next

What's proven vs assumed — stated plainly.

Formal ceiling on XOR-heavy rewrites

Mitigated by the tiered miter (sim-verified < proven; residual risk quantified). Fix: XOR-aware EC or the GF(2) linear checker.

Coverage

3 of 7 IPs deeply validated; framework generalizes to the rest via config.

Autonomy

Proposer runs live on Gemini; earlier wins were human-seeded to validate the gate first.

Metric

Official PPA weighting still pending — strategy stays general (correctness-first, then Pareto).

Key takeaways

Verify, so you can optimize hard.

  • Verification-gated optimization — aggressive PPA search that cannot ship a functional regression → built for hidden-test judging.
  • Tiered, honest confidence — proven → sim-verified → refuted, instead of pretending everything is proven.
  • Reusable, config-driven framework — 3 IPs, Verilog + SystemVerilog, two synth flows, in the official Docker.
  • Real, gated wins — −3.19% area, timing −282 → −9 ps (+ live autonomous results).
